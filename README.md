# file_transfer

Небольшой асинхронный TCP-сервис для передачи файлов, написанный на Rust. Сервер принимает аутентифицированные загрузки, потоково записывает их на диск и публикует завершённые файлы без перезаписи существующих.

> Это учебный проект, а не защищённый сервис для работы в интернете. Протокол с общим токеном не шифруется: используйте его только в доверенной сети или внутри VPN. Любой, кто может перехватить соединение, способен получить и повторно использовать bearer-токен. Не открывайте порт напрямую в публичный интернет.

## Возможности

- Tokio для TCP I/O и отдельных задач на каждое соединение; платформозависимый код polling не используется.
- Ограничение размера загружаемого файла, количества одновременных соединений, времени простоя и общей продолжительности передачи.
- Аутентификация по общему токену, обязательная как на клиенте, так и на сервере.
- Потоковая передача с использованием буфера фиксированного размера; содержимое файла целиком не загружается в оперативную память.
- Запись во временный файл с уникальным именем, его синхронизация с диском и атомарная публикация посредством hard link в той же директории. Существующие файлы никогда не перезаписываются.
- Структурированные логи через `tracing`; уровень подробности настраивается с помощью `RUST_LOG`.

## Требования

- Стабильная версия Rust с Cargo и поддержкой edition 2024.
- Сетевая доступность между отправителем и получателем.

```powershell
cargo fmt --all -- --check
cargo test --all-targets
cargo build --release
```

## Запуск сервера

Задайте случайный токен размером не менее 16 байт UTF-8 в переменной окружения. Сгенерируйте его один раз с помощью криптографически безопасного генератора случайных чисел и используйте одинаковое значение на сервере и всех авторизованных отправителях.

Не добавляйте токен в систему контроля версий и не помещайте его в историю командной оболочки.

PowerShell:

```powershell
$bytes = New-Object byte[] 32
[Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
$env:FILE_TRANSFER_TOKEN = [Convert]::ToBase64String($bytes)
```

Запуск сервера на локальной машине:

```powershell
cargo run --release --bin server -- --listen 127.0.0.1:7878 --output-dir .\received
```

Для доступа с других машин в локальной сети привяжите сервер к сетевым интерфейсам:

```powershell
cargo run --release --bin server -- --listen 0.0.0.0:7878 --output-dir C:\Transfers
```

`0.0.0.0` — это адрес, на котором сервер принимает соединения, а не адрес, к которому подключаются клиенты.

## Отправка файла

В отдельном терминале на компьютере отправителя установите `FILE_TRANSFER_TOKEN` в точно такое же значение, как на сервере, затем запустите:

```powershell
cargo run --release --bin client -- "C:\path\to\file.zip" --server 192.168.1.25:7878
```

Для тестирования на той же машине используйте `--server 127.0.0.1:7878`.

В Linux/macOS, например:

```sh
FILE_TRANSFER_TOKEN='your-token' \
  cargo run --release --bin client -- ./file.zip --server 192.168.1.25:7878
```

Получатель сохраняет файл под исходным именем в настроенной выходной директории.

Если файл с таким именем уже существует, загрузка отклоняется. Сервер не заменяет существующие файлы.

Каждое TCP-соединение используется для передачи одного файла.

Проверить корректность передачи можно сравнением хешей:

```powershell
Get-FileHash "C:\path\to\file.zip" -Algorithm SHA256
Get-FileHash "C:\Transfers\file.zip" -Algorithm SHA256
```

## Конфигурация и значения по умолчанию

| Опция | По умолчанию | Описание |
| --- | ---: | --- |
| Сервер `--listen` | `127.0.0.1:7878` | IP-адрес и TCP-порт для прослушивания |
| Сервер `--output-dir` | `received` | Директория назначения |
| Сервер `--max-file-size` | 1 GiB | Максимальный размер принимаемого файла в байтах |
| Сервер `--max-connections` | 32 | Максимальное количество одновременных соединений/передач |
| Клиент `--server` | `127.0.0.1:7878` | IP-адрес и TCP-порт получателя |
| Клиент `--max-file-size` | 1 GiB | Локальное ограничение размера файла перед отправкой |
| `--idle-timeout-secs` | 30 | Максимальное время ожидания следующей операции с сокетом |
| `--transfer-timeout-secs` | 3600 | Максимальная общая продолжительность одной передачи |

Сервер самостоятельно применяет свои ограничения. Ограничения на стороне клиента являются лишь проверками удобства и не являются границей безопасности.

Изменяйте значения осознанно, например:

```powershell
cargo run --release --bin server -- --listen 0.0.0.0:7878 --output-dir C:\Transfers --max-file-size 5368709120 --max-connections 8
```

`FILE_TRANSFER_TOKEN` обязателен для обоих бинарных файлов и должен содержать от 16 до 128 байт UTF-8.

Токен передаётся в протоколе как bearer credential и не шифруется. Защищайте его соответствующим образом.

Для более подробных логов установите:

```powershell
$env:RUST_LOG = "debug"
```

## Протокол передачи

Все целочисленные поля используют порядок байтов big-endian.

Одно TCP-соединение передаёт один файл в следующем порядке:

1. Клиент отправляет 2-байтовую длину токена, затем от 16 до 128 байт самого токена.
2. Сервер отправляет 1-байтовый статус (`0` означает успешную аутентификацию).
3. Клиент отправляет 2-байтовую длину имени файла, байты имени в UTF-8 (от 1 до 255 байт), затем 8-байтовый размер файла.
4. Сервер проверяет запрос и отправляет 1-байтовый статус готовности/отказа.
5. Клиент отправляет ровно указанное количество байт файла.
6. Сервер синхронизирует временный файл, публикует его без замены существующего файла и отправляет итоговый 1-байтовый статус.

Значения статуса:

| Значение | Описание |
| ---: | --- |
| `0` | Успешно |
| `1` | Ошибка аутентификации |
| `2` | Сервер достиг лимита соединений |
| `3` | Запрос или передача отклонены |

TCP является потоком байтов, поэтому чтение данных не должно предполагать, что границы операций `write` на отправителе совпадают с границами операций `read` на получателе.

## Текущие ограничения безопасности и эксплуатации

- **TLS отсутствует.** Перехваченный токен может быть повторно использован. Используйте сервис только в доверенной LAN или через VPN. Для работы в недоверенной сети перед использованием необходимо добавить TLS с проверкой сертификата.
- **Нет идентификации пользователей.** Используется единый общий токен.
- **Нет квот на пользователя.**
- **Нет ограничения частоты запросов (rate limiting).**
- **Нет проверки файлов на наличие вредоносного содержимого.**
- **Нет журнала аудита загрузок.**
- Выходная директория должна быть доступна для записи только сервисной учётной записи и должна контролироваться на предмет заполнения диска.
- Резервное копирование и политика хранения файлов должны настраиваться отдельно.
- Временные файлы `.part` могут остаться после аварийного завершения процесса или отключения машины. Периодически проверяйте и удаляйте оставшиеся временные файлы.
- Публикация через hard link требует, чтобы файловая система поддерживала жёсткие ссылки.
- Временный и итоговый файл намеренно находятся в одной директории, чтобы публикация через hard link была атомарной.
